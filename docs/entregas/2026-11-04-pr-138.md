# 2026-11-04 · PR #138 · Registro de corridas: rc desconocido cuando el código de la línea no es el de npm

- **Encargo:** «Ejecuta los pendientes como un arquitecto senior con las Skills instaladas y las propuestas de mejora; no pares hasta no tener resuelto». Es la mejora propuesta al cerrar el PR #137. Preguntado en la sesión, el dueño eligió **«Apuntar desconocido»**.

## Cerrado

**El problema.** Claude Code solo ve el código de salida de la línea entera, que es el de su último programa. Con npm seguido de `| tail`, de `; echo rc=$?` o de `|| true`, o lanzado en segundo plano, un fallo de npm llegaba al registro como rc=0.
- `pre-push.sh` lo daba entonces por un `verificar` en verde, justo antes de un push que despliega.
- Se midió con dos `npm run reservar … | tail` que fallaron y quedaron con rc=0.

**Lo que cambia:**
- `.claude/hooks/lib-comando.js`, `rcEsDeNpm(cmd)`. El código es fiable solo si detrás de npm hay `&&`, o `|` con `set -o pipefail` antes.
  - Lo que va entre comillas no separa.
  - Ante la duda, desconocido: un caso que no se entiende cuesta una pregunta de más, nunca un verde falso.
- `aprendizaje.sh` apunta `rc: null`, con una `note` que dice por qué, cuando el código no es fiable o la corrida va en segundo plano.
- `lib-fallos.js`: un `rc: null` ni corta ni alarga la racha del recordatorio del asesor (PR #137).
- `pre-push.sh`: si el último `verificar` es de resultado desconocido y más reciente que el último verde, lo dice y pide confirmación (`ask`: avisa, no bloquea), con cómo correrlo para que cuente.
- `skill-usage-insights`: `rc: null` queda fuera de la tasa de éxito. Su copia para Copilot se regeneró.

**Un fallo que cazó el registro real.** La primera versión tomaba el `|` de `grep -E "^# (pass|fail)"` por una tubería y apuntó un `verificar` como desconocido. Ahora las comillas se vacían antes de partir la línea, y el caso está en la prueba.

**Pruebas:**
- `test/aprendizaje-hook.test.js`: nueve formas de la línea con su rc, y el desconocido dentro de la racha.
- `test/pre-push-hook.test.js`: el desconocido pide confirmación, y un verde posterior lo calla.
- Caen los dos sabotajes: rc siempre 0, y `pre-push.sh` sin el caso desconocido.

**Verificación:** `npm run verificar`, 1.425/1.425 y lint sin errores (los 9 avisos ya estaban). El hook real lo registró con rc=0, porque detrás solo había `&&`. No toca `public/` ni `server/`.

## Estado

**Para quien trabaje aquí:** `npm run verificar` cuenta para el aviso antes de empujar si se corre sin nada detrás, con `&&` detrás (`npm run verificar > log 2>&1 && grep … log`) o con `set -o pipefail` antes de la tubería. Con `| tail` a secas, el aviso pedirá confirmación.

**Mejora propuesta:** ninguna que merezca la pena. `auditar` se queda como estaba: un `auditar` de resultado desconocido no cuenta, y sin ninguno en verde `pre-push.sh` no habla de la auditoría (la regla de siempre). CI la corre y falla cerrado.

**Criterio que conviene conservar:** un registro de corridas solo es fiable si sabe qué no vio. Un código de salida que no es el del comando se apunta como desconocido, nunca como éxito.

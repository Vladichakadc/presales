# 2026-11-01 · PR #106 · npm run reservar: el tema se reserva en GitHub antes de escribir código

- **Encargo:** «EJECUTA PENDIENTES Y MEJORA PROPUESTA»; la mejora propuesta al cerrar el PR #63.

## Cerrado

El 2026-10-28 tres sesiones hicieron la misma mejora (PR #60, #62 y #63) porque un tema solo aparecía en `npm run traspasos` con el primer push de su rama, tras una hora de trabajo. `npm run reservar -- <tema> --archivos "…"` (`scripts/reservar.js`) lee lo mismo que `traspasos` (traspasos de las ramas y archivos de los PR abiertos sin traspaso) y se niega, con quién y en qué archivo, si algo choca: misma ruta o carpeta que la contiene; `PENDIENTES.md`, `RELEVO.md`, `CLAUDE.md`, `docs/entregas/` y `docs/traspaso/` no cuentan; un traspaso «cerrado…» no choca; una rama sin commits hace más de tres días se señala y solo `--aunque <rama>` la pasa por alto, dejándolo dicho en el traspaso. Si está libre, empuja `claude/<tema>` con su traspaso («reservado») armado en un índice temporal sobre `origin/main`, sin tocar el árbol de trabajo y **sin `--force`**: si dos sesiones reservan a la vez, GitHub rechaza el segundo push. `--comprobar` solo mira. Esta rama se reservó con él. `test/reservar.test.js` (10 casos, sin red, con un origin local) prueba las reglas, la reserva, el choque, `--aunque` y la carrera; con `--force` en el push la de la carrera se pone en rojo. La regla está en `CLAUDE.md` y en `docs/traspaso/README.md`.
